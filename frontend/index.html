Como funciona la autenticacion en esta API

La API usa JWT (JSON Web Tokens) con dos tipos de token:

  • access_token - Valida por 30 minutos. Se envia en el header Authorization: Bearer <token> para acceder a rutas protegidas.
  • refresh_token - Valida por 7 dias. Se usa para obtener un nuevo access_token sin volver a loguearse.
1. POST /register → 2. POST /login → 3. Recibes tokens → 4. Usas Bearer en header

Middleware: Antes de cada peticion, el middleware verifica que el access_token exista en Redis. Si no existe o expiro, devuelve 401.

Flujo de vida de un Token JWT

  • Creacion: Al hacer login, el servidor genera access_token (30min) y refresh_token (7 dias). Ambos se guardan en Redis.
  • Uso: En cada peticion protegida, el middleware envia el access_token a Redis para verificar que sigue activo.
  • Refresh: Cuando el access_token expira, se envia el refresh_token para obtener uno nuevo. El viejo se borra de Redis.
  • Logout: Ambos tokens se borran de Redis, invalidando la sesion.

Estructura del JWT (Payload)

Un JWT tiene 3 partes separadas por puntos: header.payload.signature

El payload contiene:

  • sub - ID del usuario (dueño del token)
  • exp - Timestamp de expiracion (Unix)
  • type - "access" o "refresh"

El servidor valida la firma con SECRET_KEY para asegurar que nadie lo falsifique.

Productos

Catalogo de productos. GET es publico, POST/PATCH/DELETE requieren rol admin.

Control de acceso en Productos

GET /products/ - Publico. Cualquiera puede ver los productos (no necesita token).
POST /products/ - Solo admin. El middleware verifica el token, luego require_admin() verifica que el rol en el JWT sea "admin".
PUT /products/{id} - Solo admin.
DELETE /products/{id} - Solo admin.

Ordenes

Gestion de ordenes de compra. Todas las operaciones requieren token JWT.

Control de acceso en Ordenes

POST /orders/ - Cualquier usuario logueado puede crear ordenes.
GET /orders/ - Solo ves tus propias ordenes (filtrado por user_id del token).
POST /orders/{id}/cancel - Solo el dueño puede cancelar su orden.
PUT /orders/{id}/status - Solo admin puede cambiar el estado.

Nota: El router usa get_current_user() que extrae el user_id del token JWT y lo usa para filtrar las ordenes.

Usuarios

Gestion de usuarios. Solo accesible con rol admin.

Control de acceso en Usuarios

GET /users/ - Solo admin. Lista todos los usuarios.
PUT /users/{id}/role - Solo admin. Cambia el rol de un usuario.
DELETE /users/{id} - Solo admin. Elimina un usuario.
